## Зорилго

Энэ лабораторийн ажлаар JUnit 5 ашиглан `GradeCalculator` класст unit test бичиж, ердийн утга, хязгаарын утга болон буруу оролтуудыг шалгасан.

## GradeCalculator

`letterGrade()` нь 0-100 оноог дараах байдлаар үсгэн дүнд хөрвүүлнэ.

- 90-100 → A
- 80-89.99 → B
- 70-79.99 → C
- 60-69.99 → D
- 60-аас бага → F

0-100 хязгаараас гадуур утгад `IllegalArgumentException` шиднэ.

`totalScore()` нь ирц, лаборатори, хоёр сорил болон шалгалтын онооны нийлбэрийг гаргана. Аль нэг утга сөрөг эсвэл өөрийн дээд хязгаараас хэтэрсэн үед `IllegalArgumentException` шиднэ.

## Тестүүд

Нийт **8 тестийн метод** бичсэн.

Үүнээс:

- 6 нь энгийн `@Test`
- 2 нь `@ParameterizedTest`

Parameterized test-ийн мөр бүр тусдаа test case болон ажилладаг учраас Maven-ийн бодит гаралт:

```text
Tests run: 18
```

байсан.

Үндсэн туршилтын бүтэн гаралт:

```text
results/mvn-test.txt
```

Эцсийн туршилтад бүх тест амжилттай болж `BUILD SUCCESS` гарсан.

## Хязгаарын утгууд

`letterGrade` дээр дараах хязгаарын утгуудыг шалгасан:

```text
90
89.99
60
59.99
0
100
```

Мөн -1 болон 101 утгуудад exception шидэж байгаа эсэхийг шалгасан.

`totalScore` дээр зөв нийлбэрээс гадна сөрөг ирц болон лабораторийн оноо 40-өөс хэтэрсэн тохиолдлыг шалгасан.

## Mutation test

`letterGrade()` доторх:

```java
score >= 90
```

нөхцөлийг зориудаар:

```java
score > 90
```

болгон өөрчилж тестүүдийг дахин ажиллуулсан.

Энэ үед 90 оноо A биш B болж буруу тооцогдох болсон. `letterGradeBoundaries` parameterized тестийн `90, A` тохиолдол энэ алдааг илрүүлж, Maven `BUILD FAILURE` болсон.

Mutation туршилтын гаралт:

```text
results/mvn-test-mutant.txt
```

Үүний дараа нөхцөлийг буцааж `score >= 90` болгон засаж, бүх тестийг дахин ажиллуулахад `BUILD SUCCESS` болсон.

## Дүгнэлт

Энэ лабораториор unit test нь зөвхөн ердийн утга шалгахаас илүү хязгаарын утгууд дээр чухал байдгийг ойлгосон. Ялангуяа 90 гэсэн яг заагийн утга mutation test дээр алдааг шууд илрүүлсэн нь хамгийн сонирхолтой байсан. Хэрэв зөвхөн 95 эсвэл бусад ердийн оноогоор тестэлсэн бол `>= 90`-ийг `> 90` болгосон алдаа илрэхгүй үлдэх боломжтой байсан. Parameterized test ашигласнаар ижил логиктой олон boundary value-г нэг методоор илүү цэгцтэй шалгаж болсон. `assertThrows` ашиглан зөв үр дүнгээс гадна буруу оролт дээр систем хэрхэн ажиллахыг мөн шалгасан. Mutation test нь бүх тест PASS болсон байх нь дангаараа хангалтгүй, харин тестүүд бодит алдааг барьж чадаж байгаа эсэх нь илүү чухал гэдгийг харуулсан.

## Нэмэлт — AI ашигласан тухай

AI-аар `GradeCalculator`-ийн тестийн санаануудыг шалгуулахад ердийн A, B, C, D, F утгууд болон буруу оролтыг санал болгосон. Харин тестүүдийг зөвхөн ердийн утгаар хязгаарлах нь хангалтгүй байсан тул 90, 89.99, 60, 59.99 зэрэг boundary value-уудыг тусгайлан шалгасан. AI parameterized test ашиглах санааг хурдан гаргахад хэрэгтэй байсан боловч тестийн тоо болон coverage-ийг лабораторийн шаардлагатай өөрөө тулгаж шалгах шаардлагатай байсан. Хамгийн чухал тохиолдол нь 90 онооны boundary байсан бөгөөд mutation test яг энэ алдааг илрүүлсэн. Иймээс AI нь тестийн эхний санаа гаргахад ашигтай боловч тест сайн эсэхийг mutation болон boundary testing-ээр баталгаажуулах шаардлагатай гэж үзсэн.
